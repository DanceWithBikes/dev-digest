Spec ID: SPEC-04
Status: implemented
Overview: [../../../docs/specs/eval-pipeline.md](../../../docs/specs/eval-pipeline.md)

## Scope in this module

The server package provides the feature's data layer outside the `eval` module: the eval-pipeline contracts in the server copy of `@devdigest/shared`, the add-only schema change (a batch table, a batch link and error on per-case runs, provenance columns on cases), and the seed data. The seed gives PR #482 real patches, links its review to the Security Reviewer, and adds 8 cases and 2 scored batches, so the studio and the hermetic e2e suite have data with no model call. The server's existing diff-parsing entry point re-exports the engine's parser (AC-9). The routes and use cases live in the `eval` module part.

## Module notes

- `@devdigest/shared` exists twice. Change both copies: root `AGENTS.md:27`.
- The schema change must be add-only, through `pnpm db:generate` (never hand-written; `server/src/db/migrations/**` is do-not-touch). A table that gains and loses columns in one generate hangs drizzle-kit on an interactive prompt: `server/docs/insights.md:10`.
- Migrations do not run on boot (`cd server && pnpm db:migrate`): root `AGENTS.md:28`.
- The seed is idempotent by name and never updates an existing row, so the PR #482 patch and review agent backfills need explicit "only where empty" updates (AC-64, AC-65, AC-70): `server/docs/insights.md:51`.
- Seeded PR #482 files carry no patch today (`server/src/db/seed.ts:131-139`), and the seeded review is inserted without an agent (`server/src/db/seed.ts:150-162`). The fixture patches of PR #483 and #484 have no `--- a/` / `+++ b/` header (`server/src/db/seed-fixtures.ts:53`, `:102`), so a seeded case built from them needs the header to parse (AC-68).
- `DiffHunk` holds line numbers only. To assert on added-line text (AC-67), split the raw diff on `+` lines: `server/docs/insights.md:54`.
