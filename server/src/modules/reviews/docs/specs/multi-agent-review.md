# Spec: Multi-Agent Review — server/modules/reviews

Spec ID: SPEC-06
Status: implemented
Overview: [../../../../../../docs/specs/multi-agent-review.md](../../../../../../docs/specs/multi-agent-review.md)

## Scope in this module

This module accepts the chosen agent set on the review trigger and creates one parent run for it, with every child agent run pointing to that parent. It runs up to 4 agents of a launch at the same time and keeps each agent's failure isolated. It also records the Learn decision on a finding. Grouping, conflicts, estimates and the parent read routes belong to the new multi-run service. The studio pages belong to `client/`.

## Module notes

- In-flight means `queued` OR `running` everywhere: active runs, cancel, the boot reaper, the MCP `drain` and client polling. The concurrent executor keeps that rule: runs beyond `MAX_PARALLEL_AGENTS` stay `queued` until `startAgentRun` flips them — `../insights.md:52`, `../../repository/run.repo.ts:184`, `../../constants.ts:44`.
- One agent's map-reduce chunks are sequential. With 4 agents running, concurrent provider requests reach 4 per launch, not 4 × chunks — `../insights.md:51`.
- `/runs/:id/{events,trace,cancel}` are not workspace-scoped. The parent reads in the `multi-agent` module do not copy that pattern — `../insights.md:119`.
- Cancelling a run is unreliable, because `complete()` clears the cancel flag. Concurrency makes the window more visible, but fixing it is out of scope — `../insights.md:113`.
- The MCP server calls the same `resolveTargets` / `runReview` path, so the concurrency change reaches MCP runs too (AC-25) — `../../../../mcp/compose.ts:64`.
- Finding action routes are registered only for the names in `FINDING_ACTIONS`; `learn` is now in that list and `reply` is not (AC-30) — `../../routes.ts:20`, `../../routes.ts:177`.
- Grounding and `INJECTION_GUARD` stay in reviewer-core only. Never duplicate them here — `../../AGENTS.md` (Do-not-touch).
- A diff-load failure now includes "no diff available": `loadDiff` throws when neither git nor the persisted `pr_files` patches yield a file, so such a launch fails every run (AC-24) instead of finishing `done` with no findings — `../../diff-loader.ts:33`, `../../run-executor.ts:130`.
