# Spec: Export to CI — server/modules/ci

Spec ID: SPEC-05
Status: implemented
Overview: [../../../../../../docs/specs/export-to-ci.md](../../../../../../docs/specs/export-to-ci.md)

## Scope in this module

The new `ci` module covers the server side of the feature:
- it generates the CI bundle (manifest, skills, memory file, workflow, runner bundle) and validates edited files;
- it installs the bundle as a PR on `devdigest/ci` or returns it as a zip;
- it records installations;
- it pulls and verifies CI results from GitHub, writing them as `source='ci'` agent runs;
- it serves the installations and CI runs lists.

It relies on the agents, skills and memory data, the imported repos and PRs, the GitHub adapter (through the container), and the prebuilt agent-runner bundle.

## Module notes

- Out of scope for this module: the PR feed (`server/src/modules/pulls/`) and the multi-run service (`server/src/modules/AGENTS.md` forbids importing another module's folder anyway). The PR feed's COST total sums every agent run of a PR (`server/src/modules/pulls/repository.ts:194-197`), which is why AC-74 needs no change there.
- Module layout, ring rules and `pnpm arch:check`: `server/src/modules/AGENTS.md:8-21`. GitHub access goes through the container's `GitHubClient`. `commitFiles` force-updates an existing branch (`server/src/adapters/github/octokit.ts:353-359`), so AC-42 must be checked before it is called. There is no adapter method yet for workflow runs or artifacts; adding one means interface + implementation + mock (`server/src/adapters/AGENTS.md`).
- The existing `ci_installations` / `ci_runs` tables have no `workspace_id` (`server/src/db/schema/ci.ts:4-26`), and every domain table must have one (`server/src/db/AGENTS.md`). New columns and tables go through `pnpm db:generate` only.
- Every `agent_runs` insert today hardcodes `source: 'local'` (`server/src/modules/reviews/repository/run.repo.ts:167`).
- Server secrets only via `container.secrets` (`server/AGENTS.md`, Gotchas).
- Request-validation failures are 422 across the API (`server/src/app.ts:125-129`); AC-16, AC-18, AC-20, AC-32 to AC-35, AC-131 and AC-134 follow that convention.
- `commitFiles` layers on the parent tree and never deletes (`docs/plans/export-to-ci/plan.md:24`), so AC-139 needs an explicit deletion in the install commit.
