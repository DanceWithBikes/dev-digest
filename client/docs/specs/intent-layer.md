# Intent Layer

> Introduced in: L03. Refs are `path:line` (`symbol`) at the time of writing — if a line moved,
> search for the symbol.

## Goal
Show the server-derived PR intent on the PR page so a user can check the system understood the task before trusting the review — the summary, what's in/out of scope, its confidence band, which sources resolved (and which didn't), and a way to re-run it. Renders above the description in a PR-Brief grid that L04 (Blast Radius) and L05 (PR Brief) are expected to extend.

## Open questions
- **`client/AGENTS.md`'s "fetch is mocked" claim is false, and `IntentCard.test.tsx` works around it explicitly.** There is no global fetch mock — `src/test/setup.ts` only polyfills `ResizeObserver`. `IntentCard.test.tsx:11` mocks `usePrIntent`/`useDetectPrIntent` at the component's own import specifier for exactly this reason (already recorded at `client/docs/insights.md:70`); an un-mocked render would attempt a real network call.
- **The design bundle DOES contain the source markup — a `grep` that says otherwise is checking the wrong thing.** `client/docs/design/DevDigest Design (standalone).html` is a self-unpacking bundle (44 modules gzip+base64 inside a `<script type="__bundler/manifest">`), so a raw-file `grep` for "intent" returns 0 hits regardless of content. Decompressed, module `screen_pr_detail.jsx`'s `IntentBlock` is exactly what `IntentCard`'s markup was ported from (Card chrome, `SectionLabel` icon, quoted summary, two-column scope grid) — confirmed at `client/docs/insights.md:10`. Confidence badge, sources/missing-context line, and the re-run button are NOT in the design (`IntentCard.tsx:1` doc comment) — those three were built from `@devdigest/ui` primitives verified to exist, not copied.
- **No test pins the `outOfDate` branch or the PR-Brief grid layout.** Both are visible in the component/wrapper source but not asserted by `IntentCard.test.tsx` or any `OverviewTab` test.
