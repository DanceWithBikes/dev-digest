# Spec: Export to CI — client

Spec ID: SPEC-05
Status: implemented
Overview: [../../../docs/specs/export-to-ci.md](../../../docs/specs/export-to-ci.md)

## Scope in this module

The studio adds three surfaces: the agent's CI tab, the four-step Export to CI wizard and the CI Runs page. It mirrors the CI contracts in copy 2 of `@devdigest/shared`. It relies on the `ci` module for the bundle preview, install, installations list and the CI runs list (which triggers ingest). It never talks to GitHub directly.

## Module notes

- All copy goes through `useTranslations`. The CI strings already live in `client/messages/en/ci.json`, including leftovers from an older "Publish to CI" design (`publishDialog`, `ciTab.publish`) and `exportWizard.blockMergeDesc` (`client/messages/en/ci.json:71`), which AC-102 retires (`client/AGENTS.md`, Conventions).
- The agent tab list is currently `config, skills, context, evals` (`client/src/app/agents/[id]/page.tsx:15`); the CI tab joins it. The sidebar already maps `/ci-runs` (`client/src/components/app-shell/helpers.ts:39`), but no page exists.
- The CI gate control already exists in the Config tab (`client/src/app/agents/[id]/_components/AgentEditor/_components/ConfigTab/ConfigTab.tsx:118`). AC-81 binds to the same setting rather than adding a second one.
- Components call only hooks from `src/lib/hooks`, never `fetch`. They must render in both themes (`client/AGENTS.md`, Conventions).
- A contract change here must also land in `server/src/vendor/shared` (`client/AGENTS.md`, Gotchas).
