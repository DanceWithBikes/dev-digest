# Spec: Eval Pipeline — server/src/modules/eval

Spec ID: SPEC-04
Status: implemented
Overview: [../../../../../../docs/specs/eval-pipeline.md](../../../../../../docs/specs/eval-pipeline.md)

## Scope in this module

The new `eval` module owns the HTTP surface and the use cases of the feature. It turns a decided finding into a case in one click, provides case CRUD, starts and runs eval batches in the background with frozen inputs, serves run history, batch detail and the workspace overview, and reaps orphaned batches on boot. It relies on the reviewer engine for the review call, the scorers and the diff parser (reviewer-core part), on the contracts, tables and seed data from the server package part, and on the shared review and agent repositories exposed by the container.

## Module notes

- `workspaceId` comes only from `getContext(container, req)`. Another module's folder is never imported; the review and agent data come through the container's `reviewRepo` and `agentsRepo`: `server/src/modules/AGENTS.md:15`, `:17`.
- Only `repository.ts` touches the database, only `routes.ts` imports Fastify, and services take narrow ports, not the `Container`. `pnpm arch:check` enforces this, and a new violation is never baselined: `server/src/modules/AGENTS.md:18-21`.
- Modules may not import adapters (rule `modules-depend-on-ports-not-adapters`, `server/.dependency-cruiser.cjs:67`). That is why the batch runner parses diffs through the reviewer engine (AC-8), not through the server's git adapter.
- The error envelope is `{ error: { code, message, details } }`, and `ConflictError` defaults to the code `conflict` (`server/src/platform/errors.ts:49-52`). AC-30 to AC-32, AC-45 and AC-46 need their own codes in `error.code`, so the carrier is `ConflictError(message, details, code)` with the module's `ERR.*` code as the third argument (`constants.ts:16`, `ERR`); the draft-era `AppError(<code>, message, 409)` plan was superseded.
- Request validation failures answer 422 through the global error handler: `server/src/app.ts:116-127`.
- The boot reaper for review runs runs only in the API process, and the MCP process never reaps: `server/src/app.ts:81`, `server/docs/insights.md:36`. The eval reaper (AC-58) follows the same single-API-instance assumption.
- Any `*.it.test.ts` that starts a batch must override every LLM provider it can reach. Otherwise `container.llm()` makes a real network call when a key is on the machine: `server/docs/insights.md:126`. `MockLLMProvider` stands in for OpenRouter with the id `'openai'`: `server/docs/insights.md:100`.
