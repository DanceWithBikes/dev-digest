# modules/reviews — review runs, findings, run traces

Routes: `POST /pulls/:id/review` · `/reviews` · `/findings/:id/(accept|dismiss|learn)` · `/runs/:id/(events|trace)` · `/pulls/:id/intent` (GET/POST)

- `POST /pulls/:id/review` inserts `agent_runs` and responds immediately; the work runs in `run-executor.ts` (`executeRuns` is not awaited). Body: `agentId` | `all` | `agentIds` (1–6, SPEC-05); `agentIds` is workspace-checked in one query (unknown id → 404, nothing created), may not be combined with `agentId`/`all` (400 `invalid_run_request`), and creates ONE `multi_agent_runs` parent plus its child runs in one transaction (`createMultiAgentLaunch`); the response's `multi_agent_run_id` is that parent, `null` otherwise. The parent's read side (status, groups, estimates) is the `multi-agent` module — never write it from there or read it from here.
- `POST /findings/:id/learn` only stamps `findings.learned_at` (no model call, no memory, no eval case); there is still NO `reply` route (404).
- Review logic lives in `@devdigest/reviewer-core`. This module only does I/O: diff, repo-intel context, persistence, `runBus`.
- The executor is CONCURRENT: `executeRuns` loads the diff and derives the intent ONCE, then `runInSlots` (`helpers.ts`) runs the agents with at most `MAX_PARALLEL_AGENTS` = 4 `running` at once, in request order; the rest stay `queued` until a slot frees (`startAgentRun` flips `queued` → `running` and sets `started_at`). The old sequential `for` loop is gone. In-flight still means `queued` OR `running`.
- A diff-load failure fails ALL queued agents (`failAll`); a single agent failure is isolated. `loadDiff` now THROWS `no diff available` when neither git nor `pr_files` patches give a file (a patch-less PR such as seed #482 fails instead of finishing `done` with no findings).
- `blockers` = `countBlockers(findings, agent.ciFailOn)`; the model's verdict is never the signal.
- Every run ends with `completeAgentRun` + ONE `run_traces` document + `runBus.complete(runId)` — also on failure/cancel.
- `repository.ts` is a facade over `repository/{pull,review,run}.repo.ts`.
- `POST /pulls/:id/review` has a tighter rate limit (10/min) than the global one.
- **Intent Layer (L03)**: `intent-helpers.ts`/`intent-sources.ts`/`intent-prompt.ts` are pure; `ports.ts` declares `IntentSourceCollector`/`IntentClassifier`; `compose.ts` wires the concrete `RepoIntentSourceCollector`/`LlmIntentClassifier` against the `Container` (`makeIntentEngine`, same shape as `conventions/compose.ts`). The classifier's own prompt `wrapUntrusted()`s the title/body/issue/spec (and, defense-in-depth, the files/commits digest too) — confidence/sources/missing_context are DERIVED from which sources resolved, never model-reported. `service.ts#getIntent`/`detectIntent` is the manual re-run path (`POST /pulls/:id/intent`), scoped through `getPull(workspaceId, prId)` first since `pr_intent` has no `workspace_id` of its own. `ReviewRunExecutor#deriveIntent` runs the SAME collect→classify→upsert sequence once per run, shared across every queued agent via the fanned-out `RunLogger`, between the diff load and the concurrent agent slots (`runInSlots`) — reusing the stored record when `head_sha` still matches `pull.headSha`, re-classifying when it's missing or stale. The collector+classifier pair is INJECTED into the executor's constructor by `service.ts` (`makeIntentEngine`), never pulled off the `Container` inside the executor, so the LLM call stays out of the application ring. A classifier failure there is best-effort — logged, never `failAll` — unlike a diff-load failure.
- **Project Context (SPEC-01)**: `ReviewRunExecutor#buildProjectContext` sends the documents attached to the agent, then to each ENABLED linked skill (link order; ascending paths per owner; first origin wins), for the PR's repo only, as `specs` — omitted when empty so the prompt is byte-identical to today's. Reads go through the injected `ContextDocReader` (`_shared/context-doc-reader.ts#GitContextDocReader`: head SHA → one `fetchPullHead` + `pr-<n>` → working tree); an unreadable path becomes a `not_found` trace entry + a log line, never a failed run, while a DB error fails the run like skills. The attachment tables are read via `repository/context.repo.ts` — never import `modules/project-context`. Trace `context_docs[].text` is `escapeUntrustedContent(raw)`; `specs_read` = sent paths. No extra LLM call, and MCP-triggered runs carry the docs too.

Do-not-touch: grounding and `INJECTION_GUARD` live only in reviewer-core — never duplicate them here.
- `platform/model-router.ts#routeModel(task:'intent')` is DEAD CODE — nothing calls it; never wire it up as a rival to `container.featureModel(ws, 'review_intent')`, the actual mechanism `LlmIntentClassifier` uses (`compose.ts`).
