# Spec: Eval Pipeline — client

Spec ID: SPEC-04
Status: implemented
Overview: [../../../docs/specs/eval-pipeline.md](../../../docs/specs/eval-pipeline.md)

## Scope in this module

The studio covers six pieces: the "Turn into eval case" button on every finding card, the Evals tab of the agent editor (case list, metric cards, trend chart, run history, client-side compare with the prompt diff), the Case Editor, the `/eval` Eval Dashboard, and its sidebar entry and G-then-E shortcut. It holds the client copy of the eval-pipeline contracts. It relies on the `eval` module's routes for every read and write, and it computes metric deltas and the prompt diff itself from two batch details.

## Module notes

- Components never call `fetch`; every request goes through a hook in `src/lib/hooks`. Copy goes only through `useTranslations`, and every component renders in both themes: `client/AGENTS.md:25-29`.
- `src/components` and `src/lib` never import from `src/app`, and routes never import from another route. This is why the skill-version diff helpers move to `src/lib` before the Compare view and the Case Editor reuse them. `pnpm arch:check` also cruises test files: `client/AGENTS.md:28`, `client/docs/insights.md:102`.
- `DiffViewer` takes synthetic `PrFile`s for a text diff, the way the skill-versions helper builds them: `client/docs/insights.md:108`.
- The new `/eval` route fails `pnpm typecheck` until Next generates its route types (request it once under `pnpm dev`): `client/docs/insights.md:119`.
- `src/vendor/ui/**` is extended, never rewritten. The optional chart props must keep today's defaults: `client/AGENTS.md:36`.
- Copy that already exists: `client/messages/en/eval.json` (dashboard, case editor, evals tab, breadcrumbs), `agents.json:58` (`editor.tabs.evals`) and `shell.json:24` (`nav.eval`). `/eval` already maps to the `eval` nav key (`src/components/app-shell/helpers.ts:36`), and the `FlaskConical` icon is registered (`src/vendor/ui/icons.tsx:31`). The existing `caseEditor` copy for a JSON expected-output editor (`expectedOutput`, `validJson`, `invalidJson`) and for "Run case" is obsolete. It is replaced by keys for the expectation-row editor (overview Edge cases, NFR-8).
